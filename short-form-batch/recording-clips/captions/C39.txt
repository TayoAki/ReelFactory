Let's say I am the lead data engineer. I built this ontology, so I have administrative access to everything. I ask it about revenue and inventory across the entire global company, and it gives me a comprehensive answer. Now, I share that exact same Fabric ontology file with a regional manager who only handles the West Coast. If the West Coast Regional Manager logs in and asks the exact same verbatim question, show me all global revenue and inventory risk, the agent will only return data for the West Coast. When it really, even with the same prompt. Yes. Because when the AI attempts to execute the SQL query against the underlying Lakehouse, the database recognizes the manager's identity and enforces row -level security, blocking access to the East Coast data. That is so smart. The source documentation is explicit on this point. Sharing an ontology with a user does not magically bypass workspace item permissions or database security.
