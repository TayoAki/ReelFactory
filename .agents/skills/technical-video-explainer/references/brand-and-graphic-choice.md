# Brand and explanatory-fit gates

## Brand gate — before image generation

1. Name the target product and the reference creator/product separately.
2. Retrieve official homepage, product assets or design guidance. Record exact source URLs/date and downloaded asset provenance. Treat automated branding extraction as observed styling, not an official brand manual.
3. Separate measured asset colors and published tokens from our derived surface tints. Do not invent a formal brand palette or recolor official product marks. Avoid turning every object green: neutral surfaces and explicit labels retain hierarchy.
4. Save reusable role tokens outside scene code: background, focal surface, primary symbol, secondary symbol, text, connectors, and semantic warning/success roles. Color is not the only way to distinguish relationship types.
5. Transfer composition, icon mass, spacing, depth and purposeful motion from the reference. Rebrand before generating the first master image. Pass the target palette and official assets as references alongside source composition evidence.
6. Check the generated master, every derived storyboard state and final editable scene for reference-brand leakage. A source-style reconstruction is the explicit exception; a new Fabric video is not.

Fabric evidence/theme: `content/visual-language/fabric-brand/README.md` and `theme.json`. Observed official icon emerald/teal and homepage dark teal support our mint/teal video treatment. Mint tints and retained serif typography are editorial choices. This is not a claim that Microsoft publishes those exact video tokens.

## Explanatory-fit gate — before selecting the graphic

Write: “After this beat, the viewer can ___.” Then compare options by:

- **Meaning:** does spatial structure encode the actual relationship? Property inside entity; named business edge between entities; source mapping separately. A pipeline implies processing; don't use one for mere association.
- **Concrete understanding:** does the viewer see an example or only hear a term repeated on a card? Define a type, then add a labelled instance when the lesson requires type-versus-instance understanding. Label invented values as illustrative.
- **Scope:** is this teaching vocabulary, motivation, architecture, configuration, execution or evidence? Different jobs can require different scenes.
- **Cognitive load:** introduce one distinction at a time and preserve context. Split entity/instance, source mapping and multi-source analysis if one frame becomes crowded.
- **Truthfulness:** do arrow direction, timing, color or a success mark imply copying, guaranteed accuracy, materialization or execution that the evidence doesn't support?
- **Alternative:** choose the strongest competing representation and say when it would win. “Easy to animate” is not a teaching reason.
