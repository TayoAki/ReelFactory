Your data is already in Microsoft Fabric. What if you could ask it a question, and inspect the query behind the answer?

This is Microsoft's documented data agent example. A question goes in. An answer comes back, with the steps used to retrieve it.

Here is the workflow. Create the agent. Choose its data. Then ask, inspect, and test.

In your Fabric workspace, select New Item. Search for Fabric data agent, select it, and give your agent a name.

Next, add your data source from the OneLake catalog. That could be a lakehouse, a warehouse, or a Power BI semantic model.

In Explorer, choose the relevant tables. Watch the checkboxes. You control which tables are available to the agent.

Add instructions that define your business terms. Tell the agent which source to use for different kinds of questions.

Now ask a concrete question. Microsoft's example asks how many users played Contoso games, and how many users purchased items in those games.

Here is the important part. Expand the steps and inspect the generated query. Check the filters, the tables, and the answer.

A data agent can retrieve structured answers. A question about why sales changed needs more evidence. Retrieving a number does not prove its cause.

Create. Choose. Verify. Start with one question you can check, then test more questions before you publish. That is a useful first Fabric data agent.
